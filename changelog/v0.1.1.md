# v0.1.1

Follow-up release with `constexpr` converters, converter algebra, and a batch of
code-review-driven cleanups. Fully source- and ABI-compatible with `v0.1.0` for
existing usage.

## Core

- **Determinant-based handedness**: handedness is now derived directly from the
  sign of the basis determinant (`sign(permutation) * dir_r * dir_f * dir_u`) - a
  branch-free `constexpr` expression that is the definition of orientation - in
  place of the previous rotate-normalize algorithm. Axis validation runs before it.
- **Compile-time converters**: `TransformationMeta`, `TransformationMetaBuilder`
  and the `TransformationConverter` constructor are all `constexpr`. A converter
  can now be a `static constexpr` object, and the same constructor still accepts
  values produced at runtime (e.g. a coordinate-system description received over
  the network).
- **Inversion & composition**: `TransformationConverter::inverse()` returns the
  reverse converter; `a.then(b)` composes two converters (throwing if `a`'s target
  does not match `b`'s origin). Added `origin()` / `target()` accessors.
- **3x3 matrix conversion**: `convert_matrix` now also accepts 3x3 matrices,
  treated as pure rotation/linear transforms (no scaling applied).
- **Text output**: `to_string(...)` overloads for `Axis`, `AxisDirection`,
  `Handedness`, `AxisAlignment` and `TransformationMeta`. The optional
  `<base-transformation/io.h>` header adds matching `operator<<` (kept out of the
  core so it does not pull in `<ostream>`).
- **`Ratio`**: added a real default constructor (`1/1`), removed an uncallable
  constructor template, and simplified validation.

## Traits & customization

- Concepts now require a `Traits<T, ValueType>::type` alias, so an incomplete
  trait specialization fails as a clean constraint mismatch instead of a deep
  template error.
- New `VectorAccessByIndex` / `QuaternionAccessByIndex` CRTP mix-ins synthesise
  the named component accessors (`get_x`/`set_x`/...) from a single
  `get_idx` / `set_idx` pair. They depend on neither Eigen nor PCL.

## Plugins

- Eigen: the `Matrix3` / `Matrix4` trait specializations are collapsed into a
  single `Eigen::Matrix<T, N, N>` specialization; the Eigen vector/quaternion
  traits use the new CRTP mix-ins.
- PCL: `get_idx` / `set_idx` assert `i < 3` (index 3 is the homogeneous
  component, not a spatial axis).

## Build & tooling

- `project(VERSION 0.1.1)` plus a generated `base-transformation-config-version.cmake`,
  so `find_package(base-transformation 0.1)` works.
- Added `ninja` / `ninja-tests` configure presets alongside the Visual Studio ones.
- `USE_PCL` degrades gracefully: if PCL is not found the build warns and continues
  without the PCL plugin instead of failing later.
- `TRANSFORMATION_NO_EXCEPTIONS` now reports to `stderr` and `abort()`s through a
  `[[noreturn]]` handler instead of asserting and falling through to a placeholder
  value.
- Header constants and `Presets::` factories are `inline constexpr`.
- Tests: `include(GoogleTest)`; a second test binary
  (`converter_extra_tests.cpp`) covering inversion, composition, 3x3 conversion,
  `convert_size` / `convert_scale`, presets, equality, `to_string`, and
  compile-time construction.
- Docs: Doxygen input now includes the plugin headers; the documentation workflow
  is path-filtered.
- `scripts/update_vcpkg_port.py` verifies TLS certificates (via `certifi` when
  available, otherwise the system trust store) instead of disabling verification.
